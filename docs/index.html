System Architecture

Engineered for High-Stakes Financial Integrity

Proven banking patterns preventing race conditions, balance corruption, and phantom double-spends.

Deterministic Locking

Accounts are acquired using PESSIMISTIC_WRITE in strict ascending UUID order via findAllByIdInOrderByIdAsc. This completely eliminates circular deadlock conditions across concurrent transfers.

Multi-Tier Idempotency

Combines Redis 7 fast-path caching (sub-millisecond replay) with PostgreSQL durable claims. Payloads are SHA-256 hashed to instantly reject conflicting retries with HTTP 409 Conflict.

M-Pesa B2C & Reversals

Disbursements hold funds in an intermediate SUSPENSE clearing account. On provider rejections, automated atomic reversal entries credit back the customer without manual operational intervention.

Immutable Double-Entry

Every fund movement produces balanced DEBIT and CREDIT entries with calculated running balances. The mathematical invariant $\sum \text{Credits} - \sum \text{Debits} = 0$ is continuously enforced.

Bucket4j Rate Limiting

Token-bucket rate limiting safeguards high-frequency endpoints against brute-force replay or distributed volumetric attacks, returning HTTP 429 Too Many Requests with standard retry headers.

ELK & Actuator Observability

Structured JSON logging with Logstash, unique correlation IDs on every HTTP request thread via MDC, and Prometheus metrics for real-time latency and transfer throughput tracking.
